GitHub Copilot workshop03
Grounding

Copilot works inside your repo's rules, not a toy snippet

copilot-instructions.md

  • Parity rule: change one backend, change both and update the contract
  • Structured logs with a requestId
  • Error envelope, no stack traces, no PII in logs

prompts/

  • Reusable slash commands
  • /scaffold-feature /rca
  • /fix-and-prove /tdd-next
  • /bdd-steps /sdd-plan

agents/

  • debugger: root cause, failing test, then fix
  • test-writer: tests only, never changes production code without asking
  • Per-stack *.instructions.md apply by path

Module 6 · Step 1Line-level completion

The comment is the prompt

server-node/src/routes/catalog.js
export const catalogRoutes = ({ store }) => {
  const router = Router();
  router.get('/products', ...);
  // GET /products/:sku returns one product, or throws
  // NotFoundError if the SKU doesn't exist
  router.get('/products/:sku', (req, res) => {
    const product = store.findProduct(req.params.sku);
    if (!product) throw new NotFoundError(...);
    res.json(product);
  });
  return router;
};

What to point out

It reaches for NotFoundError from src/errors.js without being told. The style comes from the file around it.

Java version

CatalogController.java, under products():

/** Returns one product by SKU, or throws NotFoundException if it doesn't exist. */

Root cause

SKU-1006 has "price": null in the seed data, and pricing assumes every product has a price.

Blast radius

Java fails too: NullPointerException in PricingService.priceLine.

The better question

Should unpriced products be sellable at all? That's a product decision, not a null check.

Wrap-up

Three habits to take back to your team

Scaffold

A spec plus repo instructions gives consistent, multi-layer code.

Debug

Evidence first. Root cause before fix. Then prove it with a test.

Test

Keep the loop small (TDD), make behavior the truth (BDD), plan before code (SDD).

Two stacks, one contract: Copilot follows your conventions, not its favorite framework.
